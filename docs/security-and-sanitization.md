# Public repository publication checklist

- [ ] Confirm no password, secret, token, private key, certificate bundle with a private key, or binding account secret is present.
- [ ] Replace real usernames, DNS zones, host identifiers, public addresses, serial numbers and user event fields if not intended for publication.
- [ ] Remove or obscure browser credentials, tokens, SSH host fingerprints, and other confidential details in screenshots.
- [ ] Keep `evidence/raw/`, `private/`, `backups/`, downloads and installers outside Git.
- [ ] Run `python3 scripts/validate_project.py` then `git diff --cached` before the push.
- [ ] Do not upload the original unredacted SOP; it contains illustrative credential strings.
- [ ] Review **Git history** for secrets; `.gitignore` does not protect previously committed files.
- [ ] Rotate any credential reused from the SOP or exposed in a screenshot/document before making the repository public.

The included config files are examples. Private data generated by test exercises must remain local, even when the repository is public.
